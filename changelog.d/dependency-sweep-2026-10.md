### Breaking — dependencies

- **The dependencies move to their latest compatible releases, and the
  compatibility floors go with them.** Bazel 9.3.1 (`.bazelversion` and the
  integration tests' Bazel), bazel-gazelle 0.54.0 as the ruleset's own
  `bazel_dep` (the 0.51.3 floor, its root-only `single_version_override` and
  `e2e/basic`'s floor test suite are gone), rules_go 0.65.0, Go 1.27.3,
  rules_rs 0.2.1, LLVM 0.8.26, protobuf 36.2, rules_nodejs 6.7.7 with Node.js
  24.22.1 as the default runtime, and pnpm 10.34.9 as the default `npm.pnpm()`
  version. LLVM 0.8.26 carries the sandbox resource-directory fix, so the
  `archive_override` and `llvm-resource-directory.patch` every workspace
  copied are deleted: a
  consumer that copied them deletes both. Bazel 9 is the only supported major:
  `module(bazel_compatibility)` says so, the Bazel 7 and 8 notes and the BCR
  presubmit's 8.x leg are gone, as are the no-op
  `--nolegacy_external_runfiles` lines and `module(compatibility_level)`.
  oxc-bazel builds against oxc 0.156, and `ts_proto_library` generates with
  protobuf-es 2.16.0, whose `@generated by` header names that version. Held
  back: pnpm stays on 10.x (pnpm 12 leaves a new workspace member that
  declares no dependencies out of an existing lockfile, so Gazelle treats it
  as foreign; pnpm 11 publishes no Intel macOS build), vitest stays on 4.x
  (the Workers pool accepts only ^4.1), toolchain_utils stays on 1.3.0
  (1.3.2's `MODULE.bazel` names a package it does not ship), Node.js stays on
  24 (rules_nodejs 6.7.7 knows no newer release), and TypeScript stays on 6.0
  where `@typescript-eslint` (`<6.1.0`) or the JavaScript compiler API that
  TypeScript 7 no longer ships needs it.
